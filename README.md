# 加密的個人筆記

這個 repo 只放一份東西：一個 `index.html`，裡面是**加密過的**內容加上一個解鎖畫面。
沒有密碼的話，就算把整份原始碼下載下來，看到的也只是 base64 的亂碼。

## 怎麼加密的

- 整份網頁（含 CSS、JS、圖片全部內嵌）先打包成單一 HTML，再用 **AES-256-GCM** 加密
- 金鑰由密碼經 **PBKDF2-HMAC-SHA256、60 萬次迭代**推導（OWASP 2023 建議值）
- GCM 的驗證標籤順便當成密碼正確與否的判斷，密碼錯會解密失敗而不是吐出垃圾
- 解密在瀏覽器端用 WebCrypto 做，沒有伺服器、也沒有任何一次把密碼送出去

**只加密 HTML 是不夠的**——圖片若還留在 `img/` 底下，直接開圖片網址就看得到。
所以建置時會把所有本機資源內嵌成 data URI，並在最後掃一次，
只要還有指向本機檔案的 `src`/`href` 就中止建置。

## 明文在哪裡

明文原稿**不在這個 repo，也不在 git 歷史裡**，放在本機的 `_locked-src/`。
建置工具（`lock.js`、`shell.html`）也在那裡。

## 要改內容或換密碼

改 `_locked-src/<站名>/` 底下的原稿，然後重跑一次加密，把產生的 `index.html` commit 上來。
指令寫在桌面的「筆記密碼.txt」裡。

## 為什麼不用伺服器端的密碼

因為要讓 GitHub Pages 那份鏡像也鎖得住。GitHub Pages 沒有任何驗證機制，
只有「內容本身就是密文」這條路能同時鎖住兩個網址。
